# tpmk_analyzer


1. `filter.py`: фильтрация таблицы tpmk по первой цифре в колонке Код и по колонке Группа 1
Сохраняет новый файл .xlsx с позициями выбранного ТН.

2. `smart_vpr.py`: Анализ пересекающихся аналогов в двух файлах, когда в прайсе конкурента код поставщика в отдельной колонке, а в tpmk код поставщика зашит в наименование товара.
Сохраняет новый файл, добавляя в файл конкурента наш артикул, наименование и СС по строкам, где артикул поставщика совпадает.

После первой загрузки файлы кэшируются в .pkl

3. `tpmk_analyzer`:


API слой: FastAPI.
Он принимает файл, создает задачу, отдает статус, результаты, метаданные.

Domain/service слой: сервисы обработки данных.
Внутри уже могут быть Excel handlers, валидаторы, трансформеры, нормализаторы, генераторы отчетов.

Worker слой: отдельные фоновые исполнители. Выполняют тяжелую загрузку, парсинг, сохранение в Postgres, построение xlsx и, в будущем, вычисление агрегатов для графиков.


Что с pandas и matplotlib
Pandas — отличная база для первого этапа, особенно если анализ идет из Excel и нужно быстро делать фильтрацию, агрегации и формирование двух выходных датафреймов. Но для будущего BI-ресурса я бы не привязывал визуализацию к matplotlib как к основному инструменту: для веб-UI обычно удобнее Plotly или другой интерактивный frontend-friendly слой, а matplotlib оставить для статичных служебных графиков или генерации файлов.

## Целевая схема
UI: отдельный web frontend.

API: FastAPI.

Workers: Celery/RQ/Arq или другой queue-based механизм для тяжелых задач.

DB: Postgres для данных, статусов, пользователей, метаданных.

Storage: файлы Excel и артефакты отдельно от БД.

Analytics layer: представления, агрегаты, метрики, semantic layer.

Visualization layer: дашборды, таблицы, графики.

Это даст нормальную эволюцию от “загрузил Excel и получил два xlsx” к “полноценный BI-ресурс” без переписывания ядра.


`Для MVP`:

endpoint загрузки Excel;

запись файла и метаданных;

постановка job в очередь;

worker читает Excel, сохраняет raw/staging данные в Postgres;

worker формирует два результирующих xlsx;

API отдает статус и ссылки на результаты.
